# Presentator 2.4.1 — Этап 12: реальные проверки PowerPoint и видео

**Основа:** актуальные исходники, присланные пользователем 03.11.2026 в `Presentator_review_20261103_151215.zip`. В их журнале **378 тестов: 358 passed, 20 ignored, 0 failed**, код завершения `cargo test --all-targets`: 0.

## Что изменено

- `src/ppt.rs`: подключены Windows-only тесты COM-помощников (6 автоматических тестов: два вида временных RPC-отказов, постоянная ошибка, неверный VARIANT/NULL, Unicode/VARIANT, преобразование ошибки файловой системы). Проверяется **реальная функция retry и типы COM**; PowerPoint для них не требуется.
- `src/ppt_stage12_native_tests.rs`: **2 opt-in интеграционных теста реального PowerPoint COM**. Слайды 1→2→1→3, а также отсутствующий PPTX→восстановление в том же Host. Проверяется реальный COM-мост, а не очередь команд.
- `src/video.rs`: только подключение тестового модуля, логика движка не изменена.
- `src/video_stage12_native_tests.rs`: **1 opt-in тест реального видеопроигрывателя**: H.264 → Ready → Play → Pos → Ended → повторный Play → Ended.
- `tests/fixtures/`: два небольших специальных файла (PPTX с 3 слайдами, MP4 длительностью 2,4 с); не используется пользовательский контент.
- `scripts/verify_stage12.ps1`: автоматическая проверка плюс осторожный **отдельный режим -Native**, пишет stdout/stderr и ExitCode в отдельные файлы, не трогает реестр.

**Рабочее поведение производства не изменено.** В `ppt.rs` и `video.rs` добавлены только тестовые блоки с `#[cfg(test)]`. Не заменяйте `src` целиком — только файлы архива.

## Установка и запуск

Распакуйте ZIP **в `C:\rust\presenter`** с заменой файлов.

Автоматические тесты (без запуска PowerPoint и видео):

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_stage12.ps1
```

Дополнительно полный старый регрессионный прогон с покрытием:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_stage10.ps1 -Coverage
```

**Настоящие Windows-интеграции** — только на тестовом компьютере, в интерактивной сессии, без других открытых процессов `POWERPNT.EXE`, с установленным PowerPoint:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_stage12.ps1 -Native -IUnderstandWindowAutomation
```

Перед `-Native` скрипт проверяет, не запущен ли PowerPoint, и требует отдельный ключ для подтверждения. При наличии открытых презентаций тест запускать нельзя. Native тест создаёт окно показа, которое может быть видно на рабочем столе; проигрыватель видео размещается за пределами экрана.

### Что ожидаем

- Прежние 358 активных тестов + 6 новых автоматических (на Windows) = **364 успешных, 23 пропущенных, 387 всего** (пока лишь прогноз; сборка Rust в среде подготовки недоступна).
- В режиме `-Native` дополнительно должны пройти все 3 специальных интеграционных теста.
- Не выполняйте `cargo test -- --ignored` без фильтра: среди остальных пропущенных есть опасные для рабочего компьютера сценарии.

Покрытие не обязано значительно увеличиться после шести тестов COM. Для реальной оценки PPT/Video понадобится собирать coverage также с запуском native-проверок, а затем исследовать оставшиеся непокрытые ветви. Пока не заявляем «100%» или проверку GUI.

Если какой-либо native тест падает, **не разворачивайте код на рабочем устройстве** и пришлите логи из пути, указанного скриптом.
