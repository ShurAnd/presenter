# Presentator 2.4.1 — этап 11: исправление сетевой загрузки и запуска тестов

Основа: файлы после этапа 10 и исправления его `verify_stage10.ps1`. Распаковать ZIP **в корень `C:\rust\presenter`** с заменой файлов.

## Изменено

- `src/net.rs` — production: блок больше оставшейся квоты `size` отклоняется **до записи** на диск, файл удаляется; ошибка записи/flush возвращается клиенту; второй `UploadBegin` удаляет неполную предыдущую загрузку и сообщает об отмене. Формат wire-протокола и нормальная загрузка файла не меняются.
- `src/net_loopback_tests.rs` — включён известный пропущенный регрессионный тест, проверяющий реальное WebSocket-поведение и отсутствие файлов; добавлены четыре теста: превышение квоты на втором блоке и восстановление на том же соединении; повторный `UploadBegin`; нулевой размер; превышение квоты фоновым файлом.
- `scripts/verify_stage10.ps1` — Windows PowerShell 5.1 не принимает нативный stderr `cargo` как ошибку: `Start-Process` перенаправляет stdout и stderr **отдельно**; результат определяется только реальным `ExitCode`.

Изменения затрагивают production-сервер намеренно: тесты нашли настоящую проблему, и одними тестами её не исправить. Перед развёртыванием на рабочий стенд нужна проверка на Windows.

## Порядок проверки

```powershell
cargo test --all-targets known_issue_upload_must_not_exceed_declared_size_on_disk -- --nocapture
cargo test --all-targets stage11_ -- --nocapture
cargo test --all-targets
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_stage10.ps1
```

Для покрытия, только после успешного прогона:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_stage10.ps1 -Coverage
```

На основании последнего пользовательского отчёта было 374 теста (353 passed, 21 ignored). После этой поставки ожидается **378 тестов (358 active, 20 ignored)**. Это **прогноз**; сборка Rust и запуск на Windows в текущей среде недоступны.

## Что проверяется реально

Тестовый `Sandbox` использует настоящий сервер `serve_client`, TCP на `127.0.0.1` со случайным портом, `tokio_tungstenite`, файловую систему и события сервера. Тесты не открывают PowerPoint, не управляют настоящими презентациями и не изменяют реестр.

## Ограничения

Проверка квоты защищает от превышения **заявленного** размера, но не задаёт независимый глобальный лимит: клиент с известным паролем всё ещё может заявить очень большой файл. Отдельно нужны ограничение общего размера загрузки / свободного места, ограничения количества подключений, аутентификация и лимит времени для незавершённых транзакций. Здесь такие параметры не вводятся, чтобы не нарушить передачу больших видео и существующий протокол.

Если тесты не прошли, не разворачивайте пакет на устройстве реального показа. Пришлите полный вывод первой ошибки. Не запускайте все `ignored` тесты на рабочем компьютере.
