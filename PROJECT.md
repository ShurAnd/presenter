# Presentator (Rust) — сводка проекта

Состояние на 09.10.2026, версия 1.0.4 (переписана с Python/PyQt6 на Rust; номер версии — в `Cargo.toml`, он же в заголовке окна и в свойствах exe).

## 1. Цель

Presentator показывает презентации (PDF и PPTX) на видеостене, а управляют им с другого компьютера.

Основной сценарий:

- **Сервер** — компьютер, подключённый к видеостене. На нём запущен Presentator в режиме сервера. Он хранит список презентаций и сам выводит показ.
- **Клиент** — компьютер оператора. Presentator подключается к серверу, загружает на него файлы и управляет показом: открыть презентацию, листать вперёд и назад, закрыть.

Тот же exe работает и автономно, без сети: локальный список и локальный показ.

Почему переписываем на Rust: в Python-версии сломан основной сценарий (подробно в разделе 6). Кроме того, Rust даёт один exe (сейчас ~58 МБ, из них 45 МБ — вшитый видеодвижок) без PyInstaller, быстрый старт и отсутствие гонок потоков в интерфейсе.

## 3. Архитектура

### Потоки

- **GUI-поток (egui).** Единственный владелец состояния: список, текущий показ, текстуры.
- **Остальные потоки** с интерфейсом не работают. Они шлют события в `std::sync::mpsc` и будят GUI через `ctx.request_repaint()`. GUI разбирает очереди в начале кадра (`App::poll`). Так устранён главный класс багов Python-версии: вызовы Qt из потока asyncio.
  - **Сервер:** отдельный поток с многопоточным tokio runtime. На каждого клиента своя задача. Остановка сервера закрывает runtime, а с ним и все соединения.
  - **Клиент:** отдельный поток с однопоточным runtime. Пока жив `ClientHandle`, живо соединение; при его уничтожении клиент отключается.
  - **Рендер PDF:** пул потоков (`render::Renderer`, половина ядер, 1–4). Документ открыт один на всех (`Arc<Pdf>`). GUI каждый кадр передаёт список нужных страниц по важности (`Renderer::want`): текущая, `PREFETCH_AHEAD` (3) следующих — на экранах больше ~9 Мпикс на одну меньше, — затем предыдущая. Новый список заменяет старый, уже рендерящиеся страницы не дублируются, ошибочные (`failed`) повторно не заказываются. Кеш текстур — от текущей−2 до текущей+3.
  - **Подготовка файла:** отдельный поток на каждый добавленный файл (подсчёт страниц).
  - **PowerPoint:** один постоянный процесс PowerShell (`ppt::Host`) на всё время работы программы, плюс поток чтения его вывода и поток опроса позиции (раз в 400 мс, только пока идёт показ). Умер или завис — запускается заново.

### Единая модель команд

Все действия описываются перечислением `Cmd`: `Open{id}`, `Next`, `Prev`, `GoTo{page}`, `Close`, `Remove{id}`, `Move{id, up}`, `Clear`.

- `App::act(cmd)`: если окно подключено клиентом, команда уходит на сервер, иначе выполняется локально через `App::apply`.
- На сервере команды от клиентов приходят как `SrvEvent::Cmd` и попадают в тот же `apply`.
- После любого изменения выставляется флаг `dirty`. В конце кадра сервер публикует новое состояние через `tokio::sync::watch`, и каждое соединение отправляет его своему клиенту. Рассылка идёт только при реальном изменении (`send_if_modified`).
- Интерфейс рисует `App::view()`: состояние сервера, если окно подключено клиентом, иначе своё. Поэтому клиент и сервер используют один и тот же код интерфейса.

### Протокол (JSON-текст и бинарные кадры WebSocket)

Клиент → сервер:
- `{"t":"Hello","password":…}` — обязательно первым сообщением, тайм-аут 5 с.
- `{"t":"Cmd","cmd":{"c":"Next"}}` и другие команды.
- `{"t":"UploadBegin","name":…,"size":…}`, затем бинарные кадры по 256 КБ, затем `{"t":"UploadEnd"}`. Загрузки идут **по отдельному соединению** (`Hello{upload:true}`, задача `upload_worker` в клиенте, по очереди): сервер не считает его клиентом и не шлёт по нему состояние; команды по основному соединению не ждут большой файл.

Сервер → клиент:
- `Welcome` или `Denied{reason}`.
- `State{state}`. Внутри `StateMsg`: `items[]` (id, имя, тип, число страниц, готовность, статус), `active`, `page`, `pages` и `message` — сообщение оператору, например ошибка PowerPoint.
- `UploadOk{name}` или `UploadErr{name, msg}`.

На сервере файл хранится под уникальным именем. Если размер не совпал или соединение оборвалось посреди передачи, недокачанный файл удаляется. Клиент передаёт сами файлы, а не свои локальные пути.

### Показ

- **Сцена** — полноэкранное окно egui (`show_viewport_immediate`, id `stage`) на сервере (и в автономном режиме). На ней всегда фон, поверх фона идут показы.
  - Фон: картинка пользователя `assets/background.png` **вшита в exe**. Файл `background.png` / `.jpg` / `.jpeg` рядом с exe, если есть, заменяет её (фон можно поменять без пересборки). Заполняет экран, лишнее обрезается. Голубая заливка — только если картинку не удалось прочитать. Нет файла — заливка `STAGE_BG` (#1f6fc8). Картинка перечитывается при каждом появлении сцены.
  - Сцена появляется при запуске сервера, при открытии любой презентации и по команде `Cmd::Background` (кнопка «Фон»).
  - **Закрыть презентацию можно только кнопкой в окне приложения (или Shift+0) либо двойным Esc (≤ 0,6 с) на экране показа.** Двойной Esc на фоне убирает сцену. Одиночный Esc нигде ничего не делает; в главном окне Esc не используется. Логика — `App::esc_press`.
  - В слайд-шоу PowerPoint одиночный Esc закрыл бы показ сам, поэтому стоит низкоуровневый хук клавиатуры (`ppt.rs`, `esc_hook`, `WH_KEYBOARD_LL` в своём потоке с циклом сообщений). Он ставится при первом показе PPTX и глотает Esc, только пока идёт наш показ PowerPoint (`grab_esc`) и на переднем плане окно класса `screenClass`; каждое нажатие уходит в приложение как `Out::ShowEsc`.
  - Курсор скрыт, пока на экране сцена (`CursorIcon::None`) или слайд-шоу (`View.PointerType = 3`, «всегда скрыт»). Сцена убрана — курсор обычный.
  - При открытии презентации сначала минимум `SWITCH_BG` (0,5 с) виден только фон — так и при переключении между презентациями всегда виден фон.
  - «Полный экран» сделан вручную: окно без рамки в (0,0), **на 1 точку выше монитора**. Флаг `with_fullscreen` у дочернего окна eframe на Windows оставлял окно 960×540, а OpenGL-окно ровно по размеру экрана Windows переводит в «полноэкранный режим», и кадры перестают выводиться (на экране остаётся белый/чёрный мусор). Размер и уровень окна дополнительно шлются командами `ViewportCommand`, потому что builder к уже созданному окну не применяется.
  - Сцена поверх всех окон (`AlwaysOnTop`) всегда, кроме времени, когда на экране слайд-шоу PowerPoint. Признак проверяется и восстанавливается напрямую через Windows на каждой перерисовке сцены (`ppt::stage_topmost`, ничего не делает, если уже так): после показа PowerPoint он терялся.
  - **Монитор для показа** (`Config::monitor` — системное имя `\\.\DISPLAY2`, пусто — основной; выбор на панели «Сеть»). На весь экран окно сцены ставится ровно на этот монитор через `SetWindowPos` в физических пикселях (`display::fit_window`, каждый кадр, если окно не на месте) — так верно и при разном масштабе мониторов; egui геометрию сцены в этом режиме не задаёт. Монитор отключён — показ на основном. Окно видео создаётся сразу на нём. PowerPoint получает монитор в свою настройку «Показ на мониторе» (`HKCU\Software\Microsoft\Office\<версия>\PowerPoint\Options\DisplayMonitor`, только если монитор выбран), а при выводе на экран окно слайд-шоу дополнительно переставляется на монитор показа (`Host::reveal`).
- **Видео** (`video.rs`) — встроенный проигрыватель, два движка за трейтом `Engine`:
  - **libmpv** (основной, `mpv.rs`) — mpv со встроенным FFmpeg, играет практически любые форматы и кодеки. DLL (121 МБ) лежит в `vendor/libmpv/libmpv-2.zip` (45 МБ), вшита в exe через `include_bytes!`, при первом видео распаковывается в `%LOCALAPPDATA%\Presentator\libmpv-<версия>\` и грузится через `LoadLibraryW`/`GetProcAddress`. Рисует в наше окно (`wid`), опции: `pause=yes`, `keep-open=yes`, без OSC/OSD/клавиш mpv, `hwdec=auto-safe`. Источник и контрольные суммы — `vendor/libmpv/README.md`.
  - **MFPlay** (запасной) — Windows Media Foundation, если libmpv не загрузился. Форматы — те, что понимает Windows. `PRESENTATOR_VIDEO=mf` принудительно включает его (для отладки).
  - Расширения файлов: `render::VIDEO_EXTS`.
  - Свой поток с циклом сообщений и своё окно без рамки на весь экран (`WS_EX_NOACTIVATE`, курсор скрыт). При открытии окно лежит **под** сценой (явно `HWND_BOTTOM`: иначе, если сцена не «поверх всех», зритель видел первый кадр до «Старт» — ошибка была до 09.10.2026 при порядке PPTX → PDF → видео), файл загружен и стоит на паузе (`VideoState::Armed`) — оператор видит в программе «готово к запуску», зритель видит фон.
  - Пробел или кнопка «Старт» (`Cmd::Play`): окно выходит поверх сцены (`HWND_TOPMOST`, без активации) и сразу `Play()` — старт мгновенный. Дальше пробел — пауза/продолжить, стрелки — перемотка ±10 с, Home — в начало. Фокус всё время у сцены, поэтому работают и двойной Esc, и все клавиши.
  - Доиграло до конца — показ закрывается, на экране фон. libmpv: свойство `eof-reached`. MFPlay: переход в «остановлено», но только если видео уже было в состоянии «играет» — сразу после `Play()` он ещё «остановлен» (до 09.10.2026 это принималось за конец, и видео закрывалось через 0,05 с). Не пошло за 8 с после «Старт» — ошибка оператору.
  - Состояние уходит клиентам в `StateMsg.video` (`VideoInfo`: состояние, позиция и длительность в секундах). Поток видео сообщает позицию только при смене секунды, длительности или паузы; мост PowerPoint не пересылает одинаковые ответы на опрос; `dirty` (рассылка) — только при реальных изменениях. Иначе в простое GUI перерисовывал окна 10 раз в секунду.
- **Пробел** — `Cmd::Play`: у видео старт/пауза, у презентаций — следующий шаг, как в PowerPoint.
- **Управление с клавиатуры из окна программы** — переключатель ⌨ в верхней панели (`Config::keyboard`, по умолчанию включён, запоминается). Зелёный: стрелки, PageUp/PageDown (на них работают кликеры), пробел, Home/End и «цифры + Enter» в окне программы управляют показом — у клиента уходят на сервер через `App::act`. Серый: клавиши в окне программы показом не управляют (кроме Enter — открыть выбранный файл). В режиме клавиатуры с кнопок снимается фокус (`surrender_focus`), иначе пробел или Enter повторно «нажимали» бы кнопку, по которой только что щёлкнули мышью. Текстовые поля не трогаются — в них печатается как обычно. На экран показа (сцену) переключатель не влияет.
- **Переход к слайду по номеру** (PDF и PPTX): поле «Слайд № [ ] Перейти» во второй строке нижней панели (работает и у клиента), либо с клавиатуры, как в PowerPoint, — набрать цифры и Enter в главном окне или на экране показа (`App::goto_typed`; номер забывается через `GOTO_TIMEOUT` = 4 с; набранный номер виден оператору в нижней панели, на стене — нет). Номер вне диапазона — сообщение «Нет слайда N». В слайд-шоу PPTX цифры и Enter обрабатывает сам PowerPoint.
- **PDF** рисуется на сцене поверх фона, на чёрном поле, страница вписывается целиком. Пока первая страница не готова, виден фон. Рендер идёт под реальный размер окна в пикселях (с ограничением максимальной стороной текстуры GPU). Заранее готовятся 3 следующие страницы и предыдущая, параллельно в нескольких потоках, — поэтому даже быстрые двойные и тройные клики кликером листают без задержки. Пока новая страница не готова, на экране остаётся предыдущая, без мигания.
- **PPTX** показывает сам PowerPoint через **постоянный мост** `ppt::Host`: один скрытый процесс PowerShell и один PowerPoint на всё время работы программы. PowerPoint запускается заранее (скрыто), как только в списке появляется первый PPTX (`Host::prewarm`). Открыть показ = открыть файл в уже запущенном PowerPoint: ~0,15–0,3 с вместо ~1,5 с. Переключение — закрыть файл и открыть другой в том же PowerPoint, без перезапуска.
  - Почему не процесс на каждый показ (как было): замер 09.10.2026 — сразу после `Quit()` новый `New-Object` подключался к ещё закрывающемуся PowerPoint, отсюда «иногда не открывается»; плюс новый показ ждал завершения старого моста.
  - Протокол (stdin): `open <sid> <в окне 0/1> <путь base64 UTF-8>`, `next`, `prev`, `goto N`, `poll`, `show`, `close`, `quit`. Ответы: `host`, `ready <sid> N hwnd`, `pos <sid> cur total`, `ended <sid>`, `error <sid> текст`. `sid` = поколение показа (`gen`), события чужих показов отбрасываются. Если `Open` не удался — одна повторная попытка с заново запущенным PowerPoint.
  - Сторож: показ не открылся за `PPT_TIMEOUT` (25 с) — мост убивается (`Host::restart`), оператору сообщение; следующий показ запустит мост заново.
  - «Вперёд» вызывает `View.Next()`, поэтому анимации проигрываются. На последнем шаге последнего слайда команда игнорируется, иначе показ закрылся бы сам.
  - Позиция берётся у PowerPoint. Если слайд переключили на сервере, клиент увидит это при следующем опросе.
  - Настройки показа, которые выставляет скрипт, помечают презентацию изменённой, и при закрытии PowerPoint спрашивал о сохранении файла «только для чтения». Поэтому скрипт ставит `$pres.Saved = -1` после запуска, на каждой команде (кроме опроса `poll` — чтобы лишний раз не дёргать PowerPoint во время смены слайда) и перед `Close()`.
  - Когда показ закрывают (наше «Закрыть», закрытие программы), скрипт закрывает презентацию. PowerPoint завершается, только если в нём не открыто ничего чужого.
  - События от старого показа отбрасываются по номеру поколения (`gen`).
  - **Запуск не виден** (`PptPhase` в `main.rs`): `Loading` — PowerPoint открывает показ за сценой, которая поверх всех окон → `Ready` — пришло `ready`, ждём `PPT_SETTLE` (0,3 с) и не меньше `SWITCH_BG` с открытия → `Lowered` — сцена опускается до обычного окна → через `PPT_LOWER` (120 мс) `Host::reveal`: окно слайд-шоу (`screenClass`, дескриптор из `ready` или поиском по классу) — `HWND_TOP`, сцена — **прямо под ним** (`SetWindowPos`), `AllowSetForegroundWindow(ASFW_ANY)` и команда `show` (`SlideShowWindow.Activate()`) → `Shown`. При закрытии слайд-шоу сразу виден фон, сцена снова поднимается наверх и забирает фокус.
  - Уровень «поверх всех» у сцены дублируется напрямую через Windows (`ppt::stage_topmost`): при смене и каждый кадр, пока PowerPoint готовит показ. Команда уровня через egui/winit после первого показа PowerPoint повторно не срабатывала, и следующее слайд-шоу появлялось поверх фона ещё во время загрузки (было видно в журнале как вспышку слайда).

### Состояние сервера и резервный сервер

- **Сбор** (`health::start`, свой поток, раз в 2 с, ~1,3 мс на замер): процессор (`GetSystemTimes`) и видеокарта 3D (PDH `GPU Engine(*engtype_3D)`) — в среднем за 10 с, чтобы короткие всплески (рендер страницы PDF) не тревожили; оперативная память (`GlobalMemoryStatusEx`); память Presentator и PowerPoint (`GetProcessMemoryInfo`; PowerPoint ищется по списку процессов, pid запоминается, если не запущен — ищется раз в 10 с); видеопамять (PDH `GPU Adapter Memory`, лимиты — DXGI; у встроенной видеокарты меньше 512 МБ своей памяти — показывается общая с ОЗУ); свободное место на диске с `presentator_files`; мониторы (`EnumDisplayMonitors`, наибольшее их число с запуска — чтобы заметить отключение); время работы; «PowerPoint не отвечает» — сколько мост ждёт ответа на запрос (`Host::lag_probe`).
- **Интерфейс не завис**: сборщик раз в 10 с будит интерфейс (`request_repaint`) и на следующем замере смотрит, вырос ли счётчик кадров `ui_frames`. Чаще не будим: каждое пробуждение перерисовывает и полноэкранную сцену (проверено: при пробуждении раз в 2 с простой рос с ~1 % до ~3 % ядра).
- **Рассылка**: сборщик отдаёт показатели клиентам сам (`ServerHandle::health_publisher`, `S2C::Health`), не через интерфейс — поэтому при зависшем интерфейсе клиенты всё равно получают показатели с «НЕ ОТВЕЧАЕТ».
- **Связь**: клиент раз в 2 с шлёт `Ping{ts}`, сервер отвечает `Pong{ts}` → задержка. Нет вестей > 6 с — «нет ответа». Показатели не приходят > 7 с при живом пинге — «программа на сервере НЕ ОТВЕЧАЕТ». Пока клиент передаёт файл, пинги ждут очереди — это не тревога. Сервер старой версии (без пинга) — показатели «недоступны», без ложной тревоги.
- **Пороги** (`health::assess`): процессор 85/97 %, ОЗУ 85/95 %, видеокарта 90/99 %, видеопамять 90/97 %, диск < 5 ГБ / < 1 ГБ, PowerPoint не отвечает 3/8 с, задержка 300/1000 мс; отключение монитора, зависание, молчание сервера — сразу «проблема».
- **Интерфейс клиента**: в верхней панели кружок и «Сервер «Зал 1»: норма / внимание / проблема» (на самом сервере — «Этот сервер (N кл.)»); щелчок открывает окно «Состояние сервера» с таблицей показателей. При «проблеме» и при неожиданном обрыве связи — красная полоса под панелью: текст проблемы, «Переключиться на резерв «…»», «Показатели» / «Переподключиться», «Скрыть».
- **Автопереподключение** (`App::reconnect`): обрыв связи не по команде оператора — клиент сам пробует подключиться снова каждые `RECONNECT_EVERY` (2 с), до `RECONNECT_TRIES` (15) попыток; в красной полосе — «переподключаюсь (попытка k из 15)», кнопка резерва доступна сразу. Связь вернулась — полоса исчезает. Неверный пароль, «Отключиться», «Скрыть», переключение на резерв — попытки прекращаются.
- **Резервный сервер** (`Config::reserve` — «адрес:порт» из списка сохранённых): выбирается на панели «Сеть» (можно и во время подключения). `switch_to_reserve` — отключиться и подключиться к резерву.
- **Синхронизация с резервом.** Галочка «Дублировать загружаемые файлы на резервный сервер» (`Config::mirror`, по умолчанию включена): каждый файл, загружаемый на основной сервер, тем же способом уходит и на резерв (`net::Uploader` — отдельное соединение «только загрузка», `App::mirror_uploader`). Клиент помнит, что последним было на экране основного сервера (`last_show`: имя файла и слайд; список сервера при обрыве очищается, а это — нет). После переключения на резерв (`Resume`, `App::continue_resume`) клиент находит там файл с тем же именем, открывает его и переходит на тот же слайд; не нашёл за 20 с — сообщение.

### Файлы на диске (рядом с exe)

- `background.png` / `.jpg` / `.jpeg` — замена вшитой картинки фона (необязательно).

Настройки (IP, порт, пароль, название, режим «в окне» — по умолчанию выключен, список серверов) — в `%APPDATA%\presenter\presentator_settings.json`. Если там файла нет, при запуске читается прежний `presentator_settings.json` рядом с exe (так хранили старые сборки). `"servers": null` читается как пустой список, а не сбрасывает все настройки.

**Список серверов** (`Config::servers`, `SavedServer`: название, IP, порт, пароль; до 20 штук, последний использованный первым). Сервер запоминается после **успешного** подключения (`App::remember_server`). В панели «Сеть» — выпадающий список «Сохранённые серверы» (выбор подставляет название, адрес, порт и пароль) и кнопка «Забыть». Две копии программы на одном компьютере пишут один файл, поэтому при сохранении список объединяется с тем, что на диске (`merge_servers`; забытые в этом сеансе не возвращаются), а при открытии панели «Сеть» подтягиваются серверы, запомненные другой копией.
- `presentator_files/` — файлы, загруженные на сервер, и `list_<порт>.json` — список сервера (порядок, имена, пути к файлам). Список и файлы **переживают перезапуск и сбой программы**: `App::save_list` пишет файл при каждом изменении списка (через временный файл, только если содержимое изменилось), `App::load_list` восстанавливает его при запуске сервера (файлы, которых нет, пропускаются) и удаляет из папки файлы, на которые не ссылается ни один `list_*.json` (недокачанные при сбое). Список хранит и восстанавливает **только запущенный сервер**, у каждого порта свой файл: копии программы на одном компьютере (клиенты, второй сервер) работают из той же папки и иначе перезаписывали бы чужой список и удаляли чужие файлы (найдено на проверке). `list.json` — файл первой сборки, читается, если файла для порта ещё нет. Файлы удаляются только по «Удалить» и «Очистить». Тест-клиенты начинают с «Очистить» и обращаются к файлам по позиции в списке.

### Ключи запуска

- `--server` — сразу запустить сервер (для автозапуска на видеостене).
- `--connect` — сразу подключиться с сохранёнными настройками.
- `--net` — открыть программу на панели «Сеть».
- `--add <файл>` (можно несколько) — добавить файл в список; вместе с `--connect` — загрузить на сервер (и на резерв). Пути с пробелами — в кавычках.
- `--watchdog` — окна нет: сторож запускает программу с остальными ключами (обычно `--watchdog --server`) и следит за ней. Сервер упал (код выхода не 0) — перезапуск через 2 с; окно сервера не отвечает на сообщения (`SendMessageTimeout(WM_NULL)`, 2 с) дольше 20 с — сторож завершает его и запускает снова; оператор закрыл сервер (код 0) — сторож тоже завершается. 5 падений подряд в первые 30 с после запуска — пауза 60 с. Журнал: `%APPDATA%\presenter\watchdog.log`. Признак Windows «не отвечает» (`IsHungAppWindow`) не годится: программу, застывшую в ожидании ввода, он зависшей не считает (проверено).
- **Автозапуск**: галочка на панели «Сеть» — `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, значение `Presentator` = `"<exe>" --watchdog --server` (через `reg.exe`). Вместе с сохраняемым списком сервер после сбоя или перезагрузки компьютера поднимается сам, с тем же списком.

Переменная окружения `PRESENTATOR_PPT_CMD` подменяет мост к PowerPoint программой с тем же протоколом (см. раздел 9). Нужна для отладки без PowerPoint.

## 4. Принятые решения и почему

| Решение | Почему |
|---|---|
| egui вместо Qt | Нативный Rust, один exe, нет проблем с потоками. Визуально повторяем оригинал: светлая тема, его цвета кнопок (#5bc0de, #d9534f, #888), индикаторы, окно 750×620. |
| Один типизированный протокол на WebSocket вместо клавиш и HTTP | В оригинале клиент обращался к несуществующим HTTP-эндпоинтам, а удалённое управление передавало нажатия клавиш, причём «назад» не было вообще. |
| Файлы передаются по тому же WebSocket | Один порт, прогресс передачи, проверка размера. Не нужно настраивать общие папки. |
| hayro для PDF вместо pdfium или mupdf | Чистый Rust: нет DLL и нет лицензии AGPL, как у mupdf. Минус в разделе 7. |
| **PPTX показывает PowerPoint, без конвертации в PDF** | Решение пользователя: нужны настоящие анимации и переходы. Первая сборка конвертировала в PDF, это убрано. |
| Мост к PowerPoint через PowerShell, а не через COM из Rust | Проще и надёжнее без возможности отладки на Windows: скрипт короткий, его легко править, а Rust-код компилируется под любую ОС. Пути передаются через переменные окружения, поэтому кириллица и кавычки не ломаются. Минус — задержка запуска около секунды. |
| Позиция PowerPoint опрашивается, а не вычисляется нами | Шаг «вперёд» может быть анимацией, а не слайдом, и листать можно прямо на сервере. Источник правды — PowerPoint. |
| Без скрытия панели задач через WinAPI | В оригинале после падения панель задач оставалась скрытой. Полноэкранное окно и так её перекрывает. |
| «В окне» по умолчанию выключено | Решение пользователя: показ всегда на весь экран. Галочка оставлена только для теста двух экземпляров на одном компьютере. |
| Видео — libmpv, вшитый в exe, + MFPlay как запасной | Решение пользователя: «всё в программе», один exe, как в старой версии, и максимум форматов. Плата — exe ~58 МБ вместо 13 МБ и 45-мегабайтный архив в репозитории. Свой проигрыватель на голом FFmpeg отвергнут: декодирование, звук и синхронизация — много работы и риска. |
| Готовность видео — только в программе | Решение пользователя: на стене чистый фон (в старой версии была зелёная рамка). |
| Сцена с фоном, запуск показа за ней | Решение пользователя: зритель никогда не видит запуск PowerPoint или пустой экран — только фон или готовую презентацию. |
| Аудиоплеер удалён | Решение пользователя. |
| Порт 14999 и пароль `default_password` по умолчанию | Совместимость с привычками старой версии. |

## 5. Что сделано

- Каркас: один exe, режимы сервер, клиент и автономный.
- Интерфейс: верхняя панель (Сеть/Список, Добавить, индикаторы сервера и клиента, Вверх, Вниз, Очистить), список с отметкой активной презентации и номером слайда, нижняя панель (Назад, Вперёд, Показать, Закрыть показ, Удалить, «Слайд N из M», строка состояния), панель «Сеть» (запуск сервера, подключение, IP, порт, пароль, «Показ в окне», подсказка). Работает перетаскивание файлов в окно.
- Сеть: авторизация паролем с понятным отказом «Неверный пароль», честная ошибка, если порт занят, синхронизация списка и позиции на всех клиентах, загрузка файлов с прогрессом; список сохранённых серверов с названиями (несколько копий программы на одном компьютере могут работать клиентами разных серверов).
- PDF: многопоточный рендер под размер окна, предзагрузка 3 страниц вперёд и одной назад, кеш текстур.
- PPTX: живое слайд-шоу PowerPoint с удалённым управлением и обратной синхронизацией позиции; постоянный мост с прогревом PowerPoint, сторож зависаний.
- Переход к слайду по номеру: поле в программе и «цифры + Enter» с клавиатуры.
- Переключатель ⌨: управление показом с клавиатуры из окна программы (в том числе с клиента).
- Состояние сервера: показатели компьютера-сервера у клиента, индикатор норма/внимание/проблема, красная полоса при проблеме или обрыве связи, резервный сервер и переключение на него одной кнопкой.
- Главное окно открывается по центру рабочей области и не выходит за её край.
- Горячие клавиши (в главном окне — при включённой ⌨ — и в окне показа): стрелки, PageUp и PageDown, пробел, Backspace, Home, End, двойной Esc. Цифры + Enter — переход к слайду. Shift+1…9 открывает презентацию по номеру, Shift+0 закрывает показ, Enter (без набранного номера) открывает выбранную.
- Сквозной тест `tests::e2e`: подключение, неверный пароль, загрузка PDF и PPTX, открытие, вперёд, назад, при `TEST_SWITCH` — переключение на другую презентацию и закрытие.
- Сцена с фоном (картинка или голубая заливка), невидимый запуск PowerPoint, фон между презентациями, двойной Esc.
- Видео: подготовка за фоном, мгновенный старт по пробелу или «Старт», пауза, перемотка, по окончании — фон. Тест `tests::e2e_video`.

**Ограничения текущей версии**
- Выбор монитора проверен только на компьютере с одним монитором: логика выбора и откат на основной при отключённом мониторе — да; реальный вывод на второй монитор и разный масштаб мониторов — нет.
- При первом запуске сервера на компьютере Windows показывает запрос брандмауэра — его нужно один раз разрешить (иначе клиенты с других компьютеров не подключатся). Пока запрос открыт, он виден поверх сцены.
- Пароль хранится и передаётся открытым текстом, шифрования (TLS) нет, сервер слушает все интерфейсы.
- Любой подключённый клиент может удалить или очистить список.
- Для старого формата `.ppt` и для `.pps` число слайдов в списке не показывается до запуска. Скрытые слайды могут дать расхождение между числом в списке и в показе.
- Если один файл загрузить дважды, в списке будет две копии.
- hayro: не поддерживаются зашифрованные PDF, режимы наложения и изолированные группы. Сложные PDF могут выглядеть иначе, чем в Acrobat. Рендер идёт на CPU без оптимизаций, поэтому первая отрисовка страницы на стене 8K может занять заметное время (соседние страницы готовятся заранее).
- Встроенный шрифт egui не содержит части эмодзи и стрелок: например, 🟢 и ← → не рисуются. В интерфейсе использованы только проверенные символы.

## 9. Как запускать и тестировать

- **Ручной тест:** два экземпляра. На одном компьютере сначала в обоих включите галочку «в окне» (иначе сцена сервера закроет весь экран; убрать её — двойной Esc). В первом **Сеть → Запустить сервер**, во втором **Сеть → Подключиться** (127.0.0.1:14999), затем **Список → Добавить**, двойной щелчок по файлу, дальше «Назад» и «Вперёд».
- **Автотест видео:** `presentator --server`, затем `TEST_VIDEO="путь\ролик.mp4" TEST_HOLD=3 cargo test --release e2e_video -- --ignored --nocapture`.
- **Автотест:** запустить `presentator --server`, затем:
  ```
  TEST_FILES="путь\a.pdf;путь\b.pptx" TEST_OPEN=1 cargo test e2e -- --ignored --nocapture
  ```
  `TEST_OPEN` — id открываемого элемента: 1 — первый загруженный файл, 2 — второй.
- **Нагрузка и утечки:** `TEST_PDF="a.pdf;b.pdf" TEST_ROUNDS=80 cargo test --release soak_render -- --ignored --nocapture` — только рендер PDF; для всей программы — `e2e_switch` с длинной `TEST_SEQ` и снаружи замер памяти процесса (`Get-Process`).
- **Переключение презентаций:** `presentator --server`, затем `TEST_FILES="a.pptx;b.pptx;c.pdf" TEST_SEQ="1,2,1,3" TEST_HOLD=4 cargo test --release e2e_switch -- --ignored --nocapture` — печатает моменты команд (unix-мс) и смену слайдов. `TEST_LAST_HOLD` — отдельное время для последней презентации (для проверки после быстрых переключений).
- Тесты запускать по точному имени (`tests::e2e --exact`): иначе фильтр `e2e` запустит и `e2e_switch`, `e2e_video`.
- **Отладка PPTX без PowerPoint:** `PRESENTATOR_PPT_CMD=<программа>` — любая программа с протоколом постоянного моста: печатает `host`, на `open <sid> …` отвечает `ready <sid> N 0`, на остальные строки — `pos <sid> cur total`.
