# Presentator 2.4.1 — регрессионные и сетевые тесты (этап 2)

Изменения только тестовые: версия Cargo.toml, поведение приложения, обработчики
команд, настройки, единственный переносимый EXE и зависимости не изменялись.

## Состав

- Сохранены 36 существующих тестов (из них 19 `ignored`).
- Включены **31 регрессионный тест** из предыдущего комплекта: 25 тестов
  `src/regression_tests.rs`, 3 в `src/net.rs` и 3 в `src/render.rs`.
- Добавлены **10 новых сетевых интеграционных тестов** в
  `src/net_loopback_tests.rs`, подключённые как вложенный модуль `net.rs`.

По исходному снимку ожидается **77 тестов (58 выполняются, 19 ignored)**.
Это расчёт по исходникам, **не подтверждённый компиляцией в этой среде**.
Подсчёт у вас в Cargo — окончательный источник истины.

## Что проверяют 10 WebSocket-тестов

1. Неверный пароль: сервер отказывает и не регистрирует клиента.
2. Команда до авторизации отклоняется.
3. Старый Hello без `version` принимается, команды и Ping/Pong передаются.
4. Авторизованный клиент получает состояние и бинарную миниатюру.
5. Отдельное соединение загрузки не считается оператором; имя файла очищается;
   содержимое сохраняется без изменений.
6. Обрезанный файл отклоняется, временный файл удаляется.
7. Загрузка фона создаёт отдельное событие `Background`.
8. Повторные соединения корректно меняют счётчик клиентов.
9. Некорректный JSON не разрушает авторизованное соединение.
10. **Настоящий `start_client()`** отправляет команду и получает состояние от
    изолированного сервера Presentator.

### Безопасность

Сервер каждого теста слушает **строго `127.0.0.1:0`** (свободный порт,
выделенный ОС). В рабочий порт `14999` ничего не отправляется. Для загрузок
создаётся уникальная папка `%TEMP%\presentator_test_...` и удаляется после
теста. GUI, PowerPoint, воспроизведение видео и реальные презентации не
запускаются. Тесты не требуют второго ПК и доступа к интернету.

> При политике Windows, запрещающей даже loopback TCP, новые тесты могут
> завершиться ошибкой привязки порта. Это ограничение окружения, а не повод
> разрешать внешние сетевые подключения для тестов.

## Установка

1. Сохраните изменения рабочего проекта: `git status` и коммит/резервная копия.
2. Распакуйте `presentator_tests_stage2.zip` в **корень** `C:\rust\presenter`
   **с заменой только перечисленных файлов**. ZIP содержит исходники только
   для тестирования; `assets`, `vendor`, `Cargo.lock` и другие файлы не трогайте.
3. В PowerShell:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_tests.ps1
   ```

4. Только сетевые тесты:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_tests.ps1 -LoopbackOnly
   ```

5. Проверка тестов и сборки EXE:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_tests.ps1 -BuildRelease
   ```

6. При наличии проблемного PDF можно отдельно проверить рендер (может быть
   медленно; нужен путь к существующему документу):

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_tests.ps1 -PdfPath 'C:\test\complex.pdf'
   ```

## Проверка изменений перед установкой

Скрипт и тестовые модули — новые или изменённые файлы. Для контроля:

```powershell
cargo test --all-targets -- --list
cargo test --all-targets
```

Обычные опасные E2E-тесты в `src/tests.rs` остались `#[ignore]`.
Не запускайте `cargo test -- --ignored` на рабочем сервере: это может менять
файлы и управлять показом. Флаг `-PdfPath` запускает два выбранных PDF-теста
по отдельности, а не всю группу ignored.

## Что здесь не проверено

Среда подготовки не содержит Rust/Windows и не имеет доступа к crates.io,
поэтому полноценные `cargo check`, `cargo test` и `cargo build --release`
выполняются **на Windows-компьютере пользователя**. Применение патча к
переданному снимку и состав ZIP проверены локально. Если Cargo выдаст
ошибку компиляции, пришлите первую ошибку вместе со строками файла.
