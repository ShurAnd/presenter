# Исправление перехода PPTX → PDF и диагностика фокуса PowerPoint

Архив содержит три файла на замену для уже установленного патча Stage 17.

## Установка

Распакуйте архив `Presentator_2.4.1_stage17_focus_fix.zip` поверх папки проекта Presentator, подтвердив замену файлов. В PowerShell из папки проекта выполните:

```powershell
cargo test --all-targets opening_pdf_after_powerpoint_reissues_stage_focus
cargo test --all-targets
```

Новый тест проверяет, что после PPTX → PDF окно сцены запрашивает фокус повторно и состояние предупреждения PowerPoint сбрасывается. Второй запуск — полный обычный набор тестов Stage 17.

## Проверка PowerPoint на Windows

Этот тест запускает настоящий PowerPoint. Выполняйте его только когда можно открыть тестовую презентацию:

```powershell
$env:PRESENTATOR_STAGE12_NATIVE = 'I_UNDERSTAND'
cargo test --all-targets stage12_native_ppt_three_slides_navigation_and_close -- --ignored --nocapture
Remove-Item Env:\PRESENTATOR_STAGE12_NATIVE
```

Нативный тест теперь требует ненулевой HWND окна слайд-шоу. Если проверка упадёт именно на HWND, приложите stderr: это означает, что PowerPoint не передал окну мониторинга пригодный дескриптор. Если HWND ненулевой, но предупреждение всё равно не появляется, приложите полный лог приложения и сообщите, был ли активен режим показа в окне.

## Ручная проверка

1. Запустите показ PPTX в оконном режиме.
2. Переключитесь на другое окно Windows. На операторе должно появиться предупреждение с кнопкой «Вернуть фокус PowerPoint».
3. Нажмите кнопку и проверьте, что клавиши пульта снова перелистывают слайды.
4. Откройте PDF сразу после PPTX. Окно сцены должно подняться поверх оставшегося окна Office; вручную закрывать PowerPoint не нужно.
5. Переключите фокус с PDF и проверьте предупреждение «Вернуть фокус PDF».

Сборка и нативные тесты требуют Windows. Если PowerShell-среда не имеет Rust toolchain/PowerPoint, сначала выполняйте обычные тесты на машине разработки, а нативную проверку — на Windows с установленным Office.
