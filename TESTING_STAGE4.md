# Presentator 2.4.1 — этап 4: команды и мост PowerPoint

Этап 4 устанавливается **поверх успешно проверенного этапа 3**.
Исходная база восстановлена из `presentator_test_sources.zip` и патчей
этапов 2–3; если после этапа 3 вы вручную меняли `src/commands.rs` или
`src/ppt.rs`, используйте проверку патча до применения и не перезаписывайте
свои изменения автоматически.

## Область изменений

Только тестовый код, подключаемый через `#[cfg(test)]`:

- `src/commands.rs` — подключение модуля тестов (3 строки);
- `src/ppt.rs` — подключение модуля тестов (3 строки);
- `src/commands_flow_tests.rs` — 14 новых тестов;
- `src/ppt_flow_tests.rs` — 10 новых тестов.

Функции приложения, протокол, `Cargo.toml`, зависимости, PowerPoint COM,
рендер, конфигурация и релизный EXE **не менялись**. Тестовые модули
вообще не компилируются в обычный release-билд.

## Что проверяют 14 тестов диспетчера команд

- Открытие PDF в синтетическом списке, установка сцены и смена показа;
- Отказ открывать отсутствующие, ещё не подготовленные и ошибочные записи;
- Навигация `Next` / `Prev` / `GoTo` с ограничением допустимых страниц;
- Сброс увеличения при смене PDF-страницы;
- Увеличение, перемещение и возврат к полной странице без выхода за границы;
- `Clock` / `Timer` / `Background` закрывают показ, но оставляют сцену;
- Предупреждение об отсутствующих связанных медиафайлах;
- Точность локального состояния списка (готов, обрабатывается, ошибка);
- Переключение между локальным и полученным от сервера состоянием;
- PowerPoint-медиа доступно только на соответствующем слайде;
- `RestorePptFocus` без готового показа не пытается управлять окном;
- Команды перелистывания PPTX не подменяют позицию до подтверждения моста;
- Состояние сцены при разных фазах показа PPTX;
- Флаг повтора меняется только у названного элемента и формат предупреждения.

**Ограничение:** для проверки реального `App::apply` создаётся тестовый
экземпляр `App`; он инициализирует его обычный `Renderer` (фоновые потоки,
PDFium, если он доступен). Не открываются пользовательские файлы, окно
PowerPoint, устройства аудио, WebSocket-порт 14999. Поскольку вызывается
производственный обработчик команд, он может **добавить записи в штатный
журнал Presentator** в `%APPDATA%\presenter\presentator.log`. Запускайте
тесты отдельно от реального мероприятия.

## Что проверяют 10 тестов моста PowerPoint

- Последовательность команд `Next`, `Prev`, `Goto`, `Show`;
- Точные аргументы `Cursor`, `Media`, `Zoom`;
- `Close` идемпотентен и не завершает рабочий поток;
- Закрытие при отсутствии показа ничего не отправляет;
- `lag_probe` сообщает показатели только для активного показа;
- `restart` сбрасывает текущий показ, ожидание и очередь;
- Команды без открытого моста не запускают PowerPoint;
- Неожиданное завершение **текущего** моста порождает `PptEvent::Error`;
- Закрытый показ не вызывает ложного уведомления;
- Позднее завершение **старого** моста после перезапуска не влияет на новый.

В этих тестах вместо реального рабочего потока используется
`std::sync::mpsc` с подставным `Worker`: не запускается PowerPoint,
COM и не посылаются команды на настоящий показ.

## Установка ZIP поверх этапа 3

1. Закройте приложение, если прямо сейчас идёт показ, и сохраните изменения
   текущего проекта в Git.
2. Распакуйте `presentator_tests_stage4.zip` в `C:\rust\presenter`
   с заменой **только перечисленных файлов**.
3. Проверьте, что тестовый модуль подключился:

   ```powershell
   cargo test --all-targets -- --list | Select-String 'flow_tests'
   ```

4. Запустите только новый набор:

   ```powershell
   cargo test flow_tests -- --nocapture
   ```

5. Если он прошёл, запустите полный безопасный набор:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_tests.ps1
   ```

6. Сгенерируйте повторный отчёт о покрытии:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_tests.ps1 -Coverage
   ```

   Основной показатель для сравнения — покрытие `commands.rs` и `ppt.rs`.
   Базовая сводка третьего этапа: 13,92% строк по проекту.
   Не обещается фиксированный прирост: проценты определит `cargo-llvm-cov`.

## Безопасный вариант установки через Git

Для чистого репозитория этапа 3 сначала используйте проверку:

```powershell
# если патч лежит в корне проекта:
git apply --check .\presentator_tests_stage4.patch
git apply .\presentator_tests_stage4.patch
```

Если проверка не проходит, **не применяйте его принудительно**: пришлите
вывод ошибки. При ручных изменениях в исходниках патч может требовать
согласования. Не запускайте весь комплект `#[ignore]` командой
`cargo test -- --ignored`: в старых сценариях есть управление настоящим
сервером и презентациями.

## Что не проверено здесь

В этой среде нет Rust toolchain и установленного PowerPoint, поэтому
`cargo test` и `cargo build --release` здесь не выполнялись. Сборка,
24 новых теста и новый процент покрытия должны быть подтверждены на Windows.
Мост PowerPoint проверен на уровне очереди команд и правил обработки
завершения потока, но это **не** полноценный COM E2E-тест PowerPoint.
