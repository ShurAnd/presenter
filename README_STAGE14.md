# Presentator 2.4.1 — Этап 14: реальные отказы и восстановление

**Основа:** переданный пользователем архив актуального проекта и его объединённый отчёт этапа 13. Базовые показатели из отчёта: **69,31% строк, 69,61% функций**; безопасный прогон — **371 passed, 23 ignored**, отдельно успешно записаны 3 нативных сценария и 50 localhost-переподключений. В отчёте этапа 13 ветви не измерялись: `0/0` здесь означает «не собрано», а не 0% покрытия.

## Что добавлено

- `src/render.rs`: безопасный тест реального PDF-рендера Hayro. Он сначала передаёт повреждённый PDF, проверяет `PageErr`, затем на том же экземпляре `Renderer` открывает минимальный корректный PDF, проверяет настоящий растровый результат. Тест не требует внешнего файла или PDFium.
- `src/ppt_stage12_native_tests.rs`: дополнительная нативная проверка завершения процесса PowerPoint и восстановления. После успешного запуска показа тест берёт PID, сохранённый мостом, вызывает существующий `Host::restart`, дожидается завершения именно этого PID и открывает ту же презентацию через новый мост.
- `src/video_stage12_native_tests.rs`: реальный проигрыватель получает повреждённый MP4 и должен выдать `Error`; затем отдельный экземпляр открывает короткий H.264-файл, запускается, сообщает прогресс и доходит до `Ended`.
- `scripts/verify_stage14.ps1`: обычный прогон, отдельный localhost-стресс и отдельно разрешаемые нативные проверки. Никакого запуска всех `ignored`-тестов.
- `scripts/coverage_report_stage14.ps1`: объединённый отчёт безопасных и выбранных дополнительных запусков. Выводит метрики строк, функций, регионов и ветвей. Ветка `-Branch` доступна только с nightly; при `0/0` отчёт явно помечает покрытие ветвей как недоступное, не трактуя это как 0%.

Производственная логика приложения и `Cargo.toml` не менялись. GUI-автоматизация не добавлялась.

## Установка

Распакуйте ZIP в корень `C:\rust\presenter`, сохраняя структуру каталогов и заменяя только одноимённые файлы из архива. Проверка изменений:

```powershell
cd C:\rust\presenter
git status --short
```

Не удаляйте имеющиеся бинарные фикстуры этапа 12. Архив подготовки к Work не содержит `tests\fixtures\stage12_three_slides.pptx` и `tests\fixtures\stage12_video.mp4`; они должны остаться в полной локальной копии проекта. Нативный скрипт остановится с понятной ошибкой, если их нет.

## Обычный прогон

Запускает стандартные тесты, не открывает PowerPoint и не запускает видео:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_stage14.ps1
```

Для исходного набора этапа 13 ожидается **372 passed и 25 ignored**: плюс один безопасный тест рендеринга и две новые нативные проверки, которые остаются пропущенными без явного запуска. Это ожидаемое число, а не результат тестирования этапа 14.

Отдельно — 50 настоящих WebSocket-переподключений только на localhost:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_stage14.ps1 -StressLoopback
```

## Нативные PowerPoint и видео

Запускайте только на тестовом Windows-компьютере, в интерактивной пользовательской сессии, когда PowerPoint закрыт и нет живого показа. Проверка восстановления намеренно завершает PID PowerPoint, который был запущен тестом; не запускайте её при открытых пользователем презентациях.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_stage14.ps1 -Native -IUnderstandWindowAutomation
```

Этот режим запускает три ранее проверенных сценария этапа 12 и два новых: завершение/перезапуск PowerPoint и отказ на повреждённом видео с последующим успешным воспроизведением исправного файла. Каждая нативная проверка запускается отдельно и пишет собственные логи в `%TEMP%\Presentator-stage14-test-*`.

## Измерение покрытия

Обычный объединённый отчёт:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\coverage_report_stage14.ps1
```

Отчёт с реальными PowerPoint/видео проверками:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\coverage_report_stage14.ps1 -Native -IUnderstandWindowAutomation
```

Ветка `-Branch` требует nightly Rust и `llvm-tools-preview`; для полного покрытия с дополнительными сценариями:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\coverage_report_stage14.ps1 -Native -IUnderstandWindowAutomation -StressLoopback -Branch
```

Результат: `target\Presentator_stage14_coverage.zip`. В нём будут HTML, JSON и текстовые метрики, список реально запущенных групп и отдельные журналы. Не запускайте эти сценарии во время показа. Если тест или coverage-прогон завершится ошибкой, пришлите соответствующие stdout/stderr логи из `%TEMP%` либо новый ZIP отчёта.

## Ограничения проверки

Эти добавления покрывают реальные точки отказа и восстановления, но не доказывают 100% надёжность и не превращают строковое покрытие в покрытие всех решений. Этап 14 нужно завершить после запуска обычного набора и двух новых нативных тестов на Windows. В этой среде подготовки `cargo` и Windows PowerPoint/Media Foundation недоступны, поэтому Rust-тесты здесь не выполнялись; ZIP следует считать подготовленным патчем до получения ваших Windows-результатов.
