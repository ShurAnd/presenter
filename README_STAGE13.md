# Presentator 2.4.1 — Stage 13: надёжность сторожа и объединённое покрытие

**Основа:** `Presentator_review_20261103_151215.zip` + все 8 файлов этапа 12 + последнее исправление `verify_stage12.ps1` (ожидание непосредственно `cargo.exe`). Выполняется поверх текущего репозитория этапа 12.

## Состав ZIP

- `src/watchdog.rs`: выделена используемая в рабочем цикле функция выбора задержки перезапуска. Для 5 и более быстрых падений сохраняется пауза 60 с, для менее 5 — 2 с; после 30 с нормальной работы счётчик начинается заново. Счётчик защищён от переполнения. Формирование строки автозапуска вынесено в чистую функцию без доступа к реестру.
- `src/watchdog.rs`: **7 автоматических тестов под Windows** на реальные границы политики перезапуска (порог, длительность работы, переполнение), экранирование Unicode/пробелов в пути, местоположение журнала и отсутствие ложного обнаружения зависания несуществующего PID. Ничего не записывает в HKCU Run.
- `scripts/stage13_process.ps1`: общий контролируемый запуск внешних процессов, раздельные stdout/stderr логи, периодический прогресс каждые 15 с, проверка кодов возврата и ограничение времени. После таймаута пытается завершить дерево дочерних процессов через `taskkill /T /F`.
- `scripts/verify_stage13.ps1`: регрессионный прогон обычных тестов. Дополнительно по явному согласию можно выполнить 50 реальных WebSocket-переподключений или 3 нативных PowerPoint/видео проверки (отдельно, по названиям, без запуска всех ignored).
- `scripts/coverage_report.ps1`: **замена старого сборщика**. Сначала выполняет `cargo llvm-cov clean --workspace`, затем накапливает профили через `--no-report` и формирует **один объединённый** HTML, текстовый и JSON отчёт. По `-Native` включаются 3 реально выполняемых интеграционных теста. По `-StressLoopback` добавляется 50 реальных подключений на 127.0.0.1.

`Cargo.toml` и форматы данных не меняются; в остальных исходниках нет изменений. Файлы фикстур из этапа 12 остаются на месте.

## Установка

Распаковать ZIP в корень проекта **с сохранением структуры каталогов и заменой только этих файлов**. Проверить `git status`.

## 1. Обычный безопасный тестовый прогон

```powershell
cd C:\rust\presenter
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_stage13.ps1
```

На Windows ожидается **371 успешный тест и 23 ignored** (прежние 364 + 7 новых). Это прогноз, **не результат выполнения под Windows**. Исполняемый код под Windows нужно проверить на компьютере пользователя. Все тесты из прошлого этапа должны остаться успешными.

Дополнительный реальный локальный стресс-тест WebSocket, без обращения к внешним серверам:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_stage13.ps1 -StressLoopback
```

## 2. Покрытие

Для обычной безопасной базы, сопоставимой с предыдущими отчётами:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\coverage_report.ps1
```

Для **объединённого** отчёта с PowerPoint и видео на отдельной Windows-тестовой машине (не во время живого показа, PowerPoint перед тестами закрыт):

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\coverage_report.ps1 -Native -IUnderstandWindowAutomation
```

Если хочется добавить к объединённому покрытию 50 реальных WebSocket-переподключений:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\coverage_report.ps1 -Native -IUnderstandWindowAutomation -StressLoopback
```

В любом варианте отчёт создаёт ZIP **`target\Presentator_stage13_coverage.zip`**. Именно его нужно прислать для следующего этапа. В архиве HTML, `summary.txt`, `summary.json`, перечень выполненных тестовых групп и журналы запусков. `target/` обычно исключён из Git.

### Безопасность

- Все стандартные тесты безопасны для реестра и не используют настоящую удалённую презентацию.
- В `-Native` запускаются настоящие PowerPoint COM и видео (краткие тестовые файлы `tests/fixtures/`), поэтому делать это только на **тестовом рабочем столе**, закрыв PowerPoint. Флаг согласия обязателен.
- Игнорируемый `watchdog::tests::autostart_roundtrip` **не запускается** — он меняет реальный ключ HKCU Run. Не запускайте все ignored-тесты одной командой.
- Процессный таймаут по умолчанию 20 минут на каждый отдельный процесс, регулируется `-TimeoutMinutes`. При таймауте дочернее дерево принудительно завершается, поэтому **не запускать проверку во время живого показа**.
- Тестовое покрытие ветвей через `-Branch` пока доступно **только на nightly**, опция экспериментальная. Обычный stable оставляет её выключенной; статистику 0/0 не следует считать проверенными ветвями.
- Скрипт `coverage_report.ps1` очищает **только** `target\presentator-coverage` и профили cargo-llvm-cov для новой серии измерений; исходники и настройки он не удаляет.

## 3. После проверки

Пришлите либо журнал ошибок тестов (`%TEMP%\Presentator-stage13-test-...`), либо `target\Presentator_stage13_coverage.zip`.

Проверки watchdog здесь изучают реальные пороги рабочего алгоритма, но **не** доказывают, что системный сторож может восстановиться после любого сбоя Windows. Мы не заявляем 100% покрытие или полную отказоустойчивость до прохождения интеграционных сценариев.
