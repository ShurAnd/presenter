# Presentator 2.4.0 — PDFium в одном EXE

**Статус:** подготовлены исходники. Сборка и запуск с настоящей PDFium DLL на Windows ещё не проверены.
Не заменяйте рабочий Presentator на мероприятии до локальных испытаний.

## Что поменялось

- Приложение поставляется **одним `presentator.exe`**, ничего рядом класть не нужно.
- PDFium 7881 (Windows x64) включается в EXE на этапе компиляции (`include_bytes!`).
- При первом запуске DLL автоматически извлекается из EXE во внутренний кэш
  `%LOCALAPPDATA%\Presentator\pdfium-7881-x64-<hash>\pdfium.dll`.
  Это **не** внешняя зависимость для установки или копирования.
- Встроенная библиотека проверяется SHA-256. При повреждении кэша выполняется повторное извлечение.
- Если доступ к кэшу запрещён или PDFium не загрузилась, показывается ошибка, а PDF
  можно показывать на Hayro, как раньше.
- Ранее добавленный контроль фокуса PowerPoint сохранён.

**Отличие от статической линковки:** физически DLL временно распаковывается во внутренний
служебный каталог пользователя, но рядом с программой нет никаких файлов.
Для полноценного запуска нужен доступ на запись в `%LOCALAPPDATA%`.

## Как собрать в Windows

Используйте **полный проект**, а не AI-экспорт (в нём отсутствуют `libmpv-2.zip`, иконки, `Cargo.lock`).

1. Создайте отдельную Git-ветку и сохраните текущую рабочую версию.
2. Примените соответствующий патч или перенесите файлы из архива.
3. Из корня проекта в PowerShell запустите:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build_release.ps1
```

Скрипт **один раз на машине сборки** скачает закреплённый выпуск PDFium 7881 x64
из https://github.com/bblanchon/pdfium-binaries/releases/tag/chromium%2F7881,
сохранит его в `vendor/pdfium/pdfium.dll`, выполнит `cargo check --all-targets`,
`cargo test` и `cargo build --release`.

Полученный файл `target/release/presentator.exe` — **единственный файл для передачи**
на компьютеры показа и управления. Пользователю не нужен интернет и не нужно
скачивать DLL. Если сборка должна выполняться без интернета, заранее выполните
`scripts/prepare_pdfium.ps1` на машине с доступом и сохраните полученную DLL
в источниках сборки. Для повторного скачивания: `scripts/build_release.ps1 -RedownloadPdfium`.

Нельзя запускать обычный `cargo build` до загрузки `vendor/pdfium/pdfium.dll`:
сборочный скрипт выдаст понятную ошибку с рекомендацией запустить `build_release.ps1`.

## Ручная функциональная проверка

1. **Удалите** старую `pdfium.dll` из папки возле старого EXE (если была).
2. Скопируйте в чистую тестовую папку **только** новый `presentator.exe`.
3. Запустите на Windows x64. Убедитесь, что PDFium доступен в «Настройки → PDF».
4. Убедитесь, что внутренняя PDFium появилась в `%LOCALAPPDATA%\Presentator`.
5. Откройте простой PDF, затем тяжёлую презентацию с градиентами и прозрачностью.
6. Проверьте перелистывание, миниатюры, zoom/pan, два монитора и удалённый пульт.
7. Переключите PDFium → Hayro → PDFium и проверьте очистку старых текстур.
8. Проверьте PPTX, видео, изображения и ранее добавленный контроль фокуса.
9. При закрытом Presentator удалите **только внутреннюю папку**
   `%LOCALAPPDATA%\Presentator\pdfium-7881-x64-*` и запустите программу снова:
   PDFium должна восстановиться **без сети**.
10. Отдельно проверьте работу при заблокированном доступе к кэшу: должно
    появиться объяснение ошибки, но сам Presentator должен продолжить работать.

Для дополнительного smoke-теста PDFium:

```powershell
$env:TEST_PDF = 'C:\path\to\complex.pdf'
cargo test --release pdfium_smoke -- --ignored --nocapture
```

Тест использует вшитую библиотеку — рядом с тестовым EXE никакой DLL не нужна.

## Ограничения

- Компиляция и работа на Windows с реальным PDF в текущем окружении не проверены.
- Если машина настроена так, что приложениям запрещена запись в LOCALAPPDATA
  или загрузка динамических библиотек из пользовательских каталогов,
  PDFium не сможет запуститься — потребуется согласовать политику с администраторами.
- Следите за лицензионными уведомлениями PDFium и его зависимостей при распространении.
