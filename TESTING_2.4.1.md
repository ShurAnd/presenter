# Presentator 2.4.1 — автоматические тесты (первый этап)

## Что сделано

Исходная версия **не повышалась**: это исключительно изменение тестового кода.
Добавлен 31 новый тест: отдельный модуль `src/regression_tests.rs`
(25 тестов) и дополнительные проверки внутри `src/net.rs` и `src/render.rs`
(по 3 теста в каждом).

Проверяются: настройки и обратная совместимость JSON; сохранённые и резервные
серверы; сетевые команды и состояние сервера; значения движка PDF; геометрия
увеличения, ограничения панорамирования и ключи кэша страниц; таймер;
диагностика связи, задержка PowerPoint и мониторы; аудиоплейлист без запуска
аудиоустройств; входные имена файлов; упаковка миниатюр; PNG; число слайдов
в PPTX и реакция на повреждённый ZIP.

Существующие тесты и помеченные `#[ignore]` E2E проверки сохранены.
**Новые автоматические тесты не запускают сервер и не изменяют файлы Presentator.**
Для проверки PPTX создаётся временный файл в системном каталоге.

## Установка

1. Зафиксировать текущую рабочую версию: `git add . && git commit -m "backup before tests"`.
2. Распаковать `presentator_test_suite_2.4.1.zip` в корень полного проекта с заменой
   перечисленных файлов. **Это не весь проект**; ресурсы и `vendor` должны остаться на месте.
3. Выполнить в **Git Bash**:

   ```bash
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./scripts/verify_tests.ps1
   ```

   Или напрямую: `cargo test --all-targets`.

4. Чтобы также собрать релиз:

   ```bash
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./scripts/verify_tests.ps1 -BuildRelease
   ```

5. Для проверки **реального PDF** (без вмешательства в текущий показ):

   ```bash
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./scripts/verify_tests.ps1 -PdfPath 'C:\test\complex.pdf'
   ```

   Это запускает существующие `pdfium_smoke` и `zoom_region_matches`.
   На больших PDF они могут выполняться долго и потреблять память.

## Проверки с реальным PowerPoint / сетью

Уже имеющиеся `e2e`, `e2e_switch`, `e2e_video`, `e2e_audio` и т.п.
**не запускаются при обычном `cargo test`**. Некоторые из них отправляют
`Cmd::Clear`, загружают файлы, открывают презентации, запускают звук/видео
и закрывают текущий показ. Запускайте их только на **отдельном тестовом
сервере** с тестовым паролем и тестовым списком, не на рабочем стенде.

## Доступная проверка и ограничения

Исходный переданный архив не содержит `assets/`, `vendor/`, `Cargo.lock` и
самого исполняемого файла. В этой среде нет Rust и Windows, поэтому **нельзя
честно утверждать, что `cargo test` уже выполнен и прошёл**. Это комплект
тестов для прогона на вашем Windows-компьютере. Не отправляйте на рабочий
стенд изменения, пока `cargo test --all-targets` и ручная проверка не пройдут.

Для оценки покрытия после успешной сборки можно установить `cargo-llvm-cov`:

```bash
cargo install cargo-llvm-cov --locked
cargo llvm-cov --html
```

Покрытие следует измерять на Windows и затем постепенно повышать; одного
числа покрытия недостаточно, чтобы подтвердить надёжность показа.
