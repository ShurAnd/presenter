# Presentator 3.0.3

Версия 3.0.3 — два укрепления надёжности по итогам ревизии кода после 3.0.2.
Протокол сети не менялся, функциональность интерфейса — тоже.

## Что изменилось

- **Сервер закрывает молчащие соединения.** В 3.0.2 клиент научился рвать тихо
  умерший канал сам; серверная сторона осталась без защиты. Мёртвое соединение
  (клиент пропал без TCP-ошибки) висело на сервере, пока не заполнялся буфер
  отправки (Health каждые 2 с — это минуты), и всё это время портило счётчик
  «Этот сервер (N кл.)», а задача и память держались зря. Теперь сервер следит
  за последним сообщением клиента (исправный пингует раз в 2 с): молчание
  дольше 30 с — соединение закрывается, счётчик выправляется, в журнал
  пишется строка «Клиент молчит N с — соединение закрыто сервером».
  Проверка включается только после первого полученного Ping: старые клиенты
  (до 2.2) и загрузочные соединения на пинги не отвечают — для них молчание
  норма, как и раньше.
- **Временный файл настроек — свой у каждой копии программы.** С 3.0.2 настройки
  пишутся атомарно — через временный файл и переименование, но имя временного
  файла было одним на всех. Две копии программы на одном компьютере пишут один
  `presentator_settings.json` (это штатный сценарий — списки серверов для того
  и сливаются с диском); при одновременном сохранении они могли столкнуться на
  одном временном файле: одна переименовала бы содержимое другой, вторая
  записала бы в журнал ложный сбой. Теперь имя содержит номер процесса
  (`config::tmp_path`), копии друг другу не мешают.

## Совместимость

- Протокол WebSocket не менялся: 3.0.3 работает с 3.0.x и 2.5.4.
- Настройки и списки читаются без миграции.

## Проверки

- `cargo test` — 403 теста, 0 падений, 29 нативных/e2e пропущены; добавлен
  `loopback_server_breaks_silent_client_connection` (клиент пингует один раз и
  замолкает, не закрывая TCP, — настоящий `serve_client` с тестовым порогом
  800 мс закрывает соединение и возвращает счётчик к нулю).
- `python scripts/scan_ui_symbols.py` — подозрительных символов нет.
- `cargo build --release` — `target/release/presentator.exe`.
- Вживую не проверено: реальный обрыв клиента без закрытия TCP со стороны
  сервера (механизм покрыт loopback-тестом с настоящим `serve_client`;
  заметить в жизни можно по журналу сервера — строка «Клиент молчит…» — и по
  счётчику клиентов, который возвращается к правде за полминуты).
