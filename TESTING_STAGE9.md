## Что меняется

- `src/commands_flow_tests.rs`: 10 проверок реального метода `App::stage_window` в headless `egui` (фон, часы, таймер, PDF, масштаб, PPT, видео в состоянии готовности, изображения и кэш текстур). Сцена принудительно в оконном режиме, viewport встроен в тестовый контекст.
- `src/ppt_flow_tests.rs`: 5 проверок очереди запросов `Host` через подставной канал; флаги `Open`, курсор, повторное открытие, штатный `shutdown`, монотонные часы. Не запускает PowerPoint и COM.
- `src/display.rs`: 4 проверки подписей, выбора и перечисления мониторов, отсутствующего HWND. Используются только безопасные операции чтения/поиска, окна не перемещаются.
- `src/health.rs`: 3 проверки фонового коллектора, оценки аварийного состояния и реального Windows-сборщика метрик. Коллектор выполняет один обычный замер (примерно через 2 секунды) и останавливается при уничтожении handle.
- `src/mpv.rs`: 2 проверки адаптера libmpv с полностью подставной таблицей указателей C API. Вызовы `set`, `command`, `get`, `events`, `check`, `error`, `drop` не загружают DLL или видео.
- `src/audio.rs`: 1 проверка обработки команд настоящим рабочим потоком на Windows, но **без загрузки треков/создания аудиоустройства**.

Всего **25 новых тестов на Windows**. Ожидаемый список: **371 тест, из которых 350 запускаются и 21 игнорируется**. Это расчёт, а не результат сборки.

Рабочее поведение приложения не изменено: в `audio.rs`, `display.rs`, `health.rs`, `mpv.rs` новый код расположен исключительно под `#[cfg(test)]`. Остальные два файла — test-only модули.

## Установка

1. **Сначала зафиксируйте успешный этап 8 в Git.**
2. Распакуйте ZIP в `C:\rust\presenter` с заменой файлов. Не распаковывайте в отдельный вложенный каталог.
3. Запустите по частям:

```powershell
cargo test stage9_scene_ -- --nocapture
cargo test stage9_host_ -- --nocapture
cargo test stage9_mpv_ -- --nocapture
cargo test stage9_audio_worker_ -- --nocapture
cargo test --all-targets
```

**Важный нюанс:** в этом окружении нет установленного Rust toolchain и Windows API, поэтому полная сборка и выполнение под Windows не проводились. Если появится ошибка компиляции или теста, отправьте лог; не считайте этот архив подтверждённым регрессионным набором до прохождения `cargo test`.

4. Если полный запуск успешный, измерьте покрытие:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_tests.ps1 -Coverage
```

Пришлите ZIP с HTML-отчётом. Следующие этапы запланируем **по фактическому приросту покрытых строк**, а не только по числу тестов.
