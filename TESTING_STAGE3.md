# Presentator 2.4.1 — этап 3: отказоустойчивость и покрытие кода

Этот комплект устанавливается **поверх уже работающего этапа 2** (77 тестов, из них
58 были пройдены на Windows). Исходники изначально предоставлены пользователем.
Все новые тесты находятся в тестовом модуле `src/net_loopback_tests.rs`.
Поведение приложения и номер версии **не менялись**. Сетевая проверка слушает только
`127.0.0.1:0`, то есть случайный порт loopback, без связи с работающим сервером.

## Что добавлено

13 обычных тестов:

- Новый клиент получает состояние и миниатюру, опубликованные до соединения.
- Три управляющих клиента одновременно подключаются, получают независимые Ping/Pong,
  отключаются; счётчик клиентов возвращается к нулю.
- Прерванная загрузка удаляет временный файл и не попадает в список.
- Передача файла в трёх WebSocket-фрагментах (два по 256 КиБ и остаток) без потери байтов.
- Пустой файл передаётся как файл нулевого размера.
- Неверные команды, JSON и неожиданные бинарные сообщения не порождают команд.
- Одновременные загрузки с одинаковым названием не перезаписывают друг друга.
- Публикация состояния не шлёт повторное уведомление при отсутствии изменений.
- Публикация миниатюр не повторяется, если id/номер страницы те же.
- Показатели здоровья сериализуются и рассылаются в правильном формате.
- Настоящий `start_client()` сообщает об отключении сервера.
- Настоящий `start_uploader()` сообщает об отсутствии локального файла.
- Настоящий `start_uploader()` передаёт файл и сообщает о прогрессе.

Два отдельных теста `#[ignore]`:

- `stress_loopback_repeated_connect_and_ping`: 50 подключений/отключений подряд,
  с отдельным явным запуском, без живого сервера.
- `known_issue_upload_must_not_exceed_declared_size_on_disk`: ожидаемое поведение,
  **пока не обеспеченное сервером** (см. «Ограничение» ниже). Этот тест специально
  пропускается, запускать его при обычной проверке не нужно.

Ожидаемое число по исходникам: **92 теста, 71 выполняемый, 21 ignored**.
Фактическое число и успешность должны быть подтверждены `cargo test` в Windows.

## Установка

1. Сохраните текущую версию в Git или сделайте копию файлов.
2. Распакуйте `presentator_tests_stage3.zip` в `C:\rust\presenter` с заменой
   указанных файлов. ZIP содержит **только изменения относительно этапа 2**.
3. Запустите PowerShell из корня проекта.

Полный безопасный набор:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_tests.ps1
```

Только сетевые тесты (`net::loopback_tests::`):

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_tests.ps1 -LoopbackOnly
```

Отдельный ограниченный стресс-тест:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_tests.ps1 -StressLoopback
```

Не запускайте все пропущенные тесты одновременно: среди старых `ignored`
есть сценарии, выполняющие действия на живом сервере / PowerPoint.

## Покрытие кода — HTML

Для Windows рекомендован стандартный Rust **MSVC** target, например
`x86_64-pc-windows-msvc`. Для `x86_64-pc-windows-gnu` cargo-llvm-cov официально
помечает ограничения поддержки. Проверить: `rustc -vV` (поле `host`).

Один раз, **при наличии интернета**, установить инструменты:

```powershell
rustup component add llvm-tools-preview
cargo install cargo-llvm-cov --locked
```

Если сборочная машина офлайн — инструменты нужно перенести или установить
заранее, скрипт **ничего не загружает и не устанавливает автоматически**.

Запуск (через существующий скрипт):

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_tests.ps1 -Coverage
```

Или напрямую:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\coverage_report.ps1 -OpenReport
```

Результат: `target\presentator-coverage\html\index.html`. Скрипт выведет
сводную статистику; `-OpenReport` открывает HTML. В отчёте отображаются
участки исходного кода, затронутые **тестами без ignored**;
это не доля успешно пройденных тестов и не гарантия отсутствия ошибок.

`cargo llvm-cov` может дополнительно пересобирать проект, очищая собственные
артефакты для достоверного покрытия. Это не изменяет исходники и не требует
удалять `target` вручную.

## Безопасность и ограничения

- GUI, презентации, устройства аудио, реальный порт 14999 и другие компьютеры
  тесты не затрагивают. Используются только временные каталоги файлов.
- Проверяется закрытие отдельных соединений, **не** автоматический повторный
  `start_client` после обрыва. Текущий клиент сам по себе не переподключается:
  реализовывать этот функционал в рамках тестового обновления мы не стали.
- **Известное ограничение загрузки:** сервер сравнивает принятый объём с
  объявленным только при `UploadEnd`. До этого временный файл может стать
  больше заявленного; явного лимита общего размера загрузки тоже нет.
  Это отдельная задача на изменение кода сервера, не исправленная в данном ZIP.
- `Cargo.toml`, `build.rs`, DLL, DLL embedding, конфигурация реального показа
  и рабочий EXE не изменены.
- Полноценная компиляция и запуск тестов на Windows здесь недоступны. На
  компьютере пользователя уже было подтверждено прохождение 58 тестов этапа 2.

## Если Cargo не видит новые тесты

Проверьте:

```powershell
cargo test --all-targets -- --list | Select-String "loopback"
```

Ранее после обновления файлов потребовалась пересборка:

```powershell
cargo clean -p presentator
cargo test --all-targets
```

`cargo clean` использовать **только если тесты не обнаруживаются**: на этом
проекте команда удаляла несколько гигабайт артефактов компиляции.
