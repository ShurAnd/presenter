# Presentator 2.4.1 — шестой этап тестирования

Этап 6 добавляет **31 активный тест** к набору пятого этапа (145 тестов, из них 124 активных и 21 `ignored`).

Ожидаемый итог после установки: **176 тестов / 155 выполненных / 21 ignored**, при условии успешной компиляции и прохождения нового набора.

## Что проверяется

- **`network.rs` (21 тест):** проверка портов, выбор резервного сервера, завершение клиентского соединения, логика восстановления презентации после переподключения, ожидание готовности файла и подтверждения открытия, защита от повторной отправки `Open`, точное восстановление страницы через `GoTo`, исключение переходов по слайдам для видео, тайм-аут восстановления, диагностика потери связи и устаревших показателей мониторинга.
- **`stage.rs` (6 тестов):** сброс состояния скрытой сцены, восстановление главного окна после закрытия сцены, поведение клиента и оконного режима, два последовательных двойных Esc (возврат к фону, затем скрытие), закрытие PDF перед скрытием сцены.
- **`video.rs` (4 теста):** доставка нескольких перемоток без слияния, порядок смены повтора/запуска/перемотки, безопасное завершение и потеря получателя команд.

Для имитации клиента используется **только локальный канал** (функция `mock_client_for_tests`, помеченная `#[cfg(test)]` в `src/net.rs`). Тесты не открывают TCP-порты, не запускают реальный PowerPoint, mpv, оконный показ или аудиоустройство. Производственный код и зависимости не меняются.

## Установка

Распаковать `presentator_tests_stage6.zip` с заменой файлов в `C:\rust\presenter`. В архиве следующие файлы:

- `src/net.rs` — вспомогательный канал доступен *только при компиляции тестов*;
- `src/commands_flow_tests.rs` — новые проверки сети и сцены;
- `src/video_flow_tests.rs` — новые проверки очереди видеокоманд;
- `TESTING_STAGE6.md` — эта инструкция.

Альтернатива: применить `presentator_tests_stage6.patch` командой `git apply` поверх пятого этапа. **Не применять одновременно ZIP и патч.** Перед заменой файлов рекомендуется сохранить рабочие изменения или выполнить commit.

## Команды проверки (PowerShell)

```powershell
cargo test network_ -- --nocapture
cargo test stage_ -- --nocapture
cargo test video_ -- --nocapture
cargo test --all-targets
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_tests.ps1 -Coverage
```

`cargo clean -p presentator` нужен только если Cargo неожиданно использует старую сборку и не видит новые тесты.

Новые тесты не компилировались на Windows в среде подготовки пакета; результат нужно подтвердить запуском на целевом ПК. `cargo test --all-targets` по умолчанию **не запускает** 21 тест с флагом `ignored` — запускать все `ignored` без предварительной проверки не рекомендуется, так как среди них есть реальные E2E-сценарии.

## Что остаётся вне автоматических проверок

Работа Windows Media Foundation/libmpv, PowerPoint COM, реальных мониторов и физический перенос вывода сцены. Рост процента покрытия кода не гарантируется заданным значением: большая часть этой логики зависит от Windows и устройств.
